# Конфигурация Beyrix

> English reference: [CONFIGURATION.en.md](CONFIGURATION.en.md).

Beyrix читает `$XDG_CONFIG_HOME/beyrix/config.toml` при запуске. Если переменная не задана, используется `~/.config/beyrix/config.toml`. Все параметры необязательны.

## Переход с Beynal

- Приложение и команда запуска переименованы: `beynal` → `beyrix`, `Beynal` → `Beyrix`, `BEYNAL` → `BEYRIX`. Cargo package, справка, заголовок окна и Wayland `app_id` (`beyrix`) используют новое имя.
- Конфигурация теперь хранится в `$XDG_CONFIG_HOME/beyrix/config.toml` или `~/.config/beyrix/config.toml`. Все прежние параметры (`theme`, `layout`, `renderer`, цвета, шрифт, история и остальные) имеют тот же формат.
- При первом запуске, если файла Beyrix ещё нет, старый `beynal/config.toml` копируется в новый путь. Существующий файл Beyrix никогда не перезаписывается, старый файл не удаляется, повторные запуски ничего не меняют. Тема, layout, renderer и прочие настройки сохраняются. Если копирование не удалось, Beyrix сообщает об ошибке и продолжает читать старый файл, не изменяя его.
- Ручной перенос: скопируйте `beynal/config.toml` в `beyrix/config.toml` при закрытом приложении. Если файл Beyrix уже существует, объедините нужные строки вручную — автоматическая миграция его не трогает.
- Новые процессы выставляют только переменные `BEYRIX_CONTROL_SOCKET`, `BEYRIX_PROMPT_THEME` и `BEYRIX_COMMAND_DIR`. Для завершения перехода CLI может однократно прочитать одноимённые `BEYNAL_*` переменные, если `BEYRIX_*` отсутствует; это совместимость только на время обновления и не является постоянным интерфейсом.
- Старый путь конфигурации `beynal/config.toml` и переменные окружения `BEYNAL_*` не используются новыми процессами. Команда `beynal` не устанавливается; внутри нового окна она временно доступна как переходный symlink для старых сессий. Старые темы, layout и renderer продолжают работать в Beyrix.

```toml
theme = "signature"
signature_compact = false
font_family = "monospace"
font_size = 16.0
padding = 12
cursor_shape = "beam"
cursor_blink = false
scrollback_limit = 10000
scroll_speed = 3
layout = "as-is"
renderer = "auto"

# Необязательные переопределения цветов
# background = "#140e24"
# foreground = "#e7e6fa"
# cursor = "#5debf7"
# selection = "#584099"
# selection_foreground = "#faf6ff"
# ansi = ["#000000", ...] # 16 цветов, обычные 0–7 и яркие 8–15
```

## Темы и приглашения

- `minimal` — тема по умолчанию. Однострочное приглашение с именем каталога и коротким указанием ветки Git.
- `developer` — однострочное приглашение с пользователем, хостом, путём и веткой. Звёздочка обозначает изменения в рабочем дереве, включая новые файлы. Код завершения появляется при ошибке.
- `signature` — фиолетовый символ ◆, голубой путь, отдельный Git-блок и код завершения при ошибке. По умолчанию ввод начинается на следующей строке. `signature_compact = true` переносит ❯ на первую строку.

`beyrix theme` показывает активную тему, `beyrix theme list` перечисляет встроенные темы. `beyrix theme set NAME` сохраняет тему, включая пользовательские комментарии и остальные параметры TOML, и отправляет обновление текущему окну. Bash применяет оформление при следующем приглашении. Графический запуск читает обычный `~/.bashrc` и добавляет приглашение через временный стартовый файл. Режим `--pty` использует обычное приглашение Bash.

Внутри Beyrix команда `beyrix` показывает справку. Из другого терминала она открывает окно. `beyrix open` явно открывает новое окно. Справка доступна через `beyrix --help`. При перенаправлении stdout и при установленном `NO_COLOR` используется обычный текст.

## Шрифт, цвета и курсор

- `font_size` — от 6 до 96 пикселей. Запасные шрифты подбирает Fontconfig. `padding` — отступ от 0 до 256 пикселей. В маленьком окне Beyrix уменьшает отступ, чтобы поместилась текстовая ячейка.
- Цвета задаются в формате `#RRGGBB`. Настройки переопределяют цвета темы. При смене темы обновляются цвета по умолчанию и первые 16 ANSI-цветов, в том числе в истории. Индексы 16–255 используют стандартную расширенную палитру. Цвета, заданные приложениями напрямую в RGB, сохраняются.
- `cursor_shape` принимает `block`, `beam` и `underline`. Приложения могут временно изменить форму через DECSCUSR и скрыть курсор. `cursor_blink = false` отключает мигание, в том числе запрошенное приложением. Без фокуса видимый курсор рисуется контуром.
- `selection` и `selection_foreground` задают фон и текст выделения независимо.

## Расположение курсора и вывода

`layout` задаёт вертикальное расположение сетки терминала и сохраняется в `config.toml`:

- `as-is` — режим по умолчанию. Bash начинает работу в левом верхнем углу, как в обычном терминале.
- `bottom` — начальное приглашение печатается в последней строке окна. Дальше терминал работает по стандартным правилам: новые строки появляются снизу, старые уходят вверх, при заполнении экрана включается обычная прокрутка. Реальная позиция курсора терминала сразу устанавливается в последнюю строку, поэтому ответы на запросы позиции (`CSI 6n`) и адресация приложений остаются корректными. Команды вроде `clear`/Ctrl+L возвращают курсор в начало экрана, как в обычном терминале.
- `bottom-input` — строка с курсором (приглашение и ввод) закреплена в последней строке окна. Остальные строки отображаются над ней в хронологическом порядке, старые сдвигаются вверх. Это чисто отображаемое смещение: координаты PTY, сетка, история и альтернативный экран не переставляются. В полноэкранных программах (nano, vim и т. п.) смещение автоматически отключается, а при прокрутке истории показывается обычный полный экран. Смещение заново включается после возврата к текущему выводу или клавиши ввода.

`beyrix layout` показывает активный режим, `beyrix layout list` перечисляет режимы, `beyrix layout set NAME` сохраняет выбор для новых окон. Переключение через конфигурацию и CLI не меняет запущенное окно. Режимы `bottom` и `bottom-input` при запуске не отправляют приложению фиктивных координат и не подменяют строки: PTY по-прежнему видит настоящую сетку и курсор.

Ограничение `bottom-input`: приложение, которое пишет в текущую строку курсора во время ввода (например, асинхронный вывод в фоне, пока Readline ждёт команду), по-прежнему использует стандартную семантику терминала и может затереть вводимый текст. Надёжно защитить незавершённый ввод можно только собственным редактором строки или разделением PTY на область вывода и отдельную строку ввода; такой хрупкий обход в Beyrix намеренно не используется.

## Графический backend

`renderer` выбирает способ вывода:

- `auto` — по умолчанию. Beyrix создаёт реальный EGL/OpenGL ES контекст на текущем Wayland-дисплее и использует OpenGL только для аппаратного рендерера (AMD/Intel/NVIDIA и т. п.). `llvmpipe`, `softpipe`, `swrast` и аналогичные программные драйверы считаются software: для них остаётся CPU-рендерер.
- `opengl` — принудительно OpenGL. Если контекст создать не удалось, Beyrix пишет ошибку в stderr и автоматически переходит на software; чёрного окна не бывает.
- `software` — существующий CPU-рендерер через `wl_shm`.
- `vulkan` — зарезервировано. Vulkan-устройства обнаруживаются и показываются диагностикой, но Vulkan-рендеринг в этой версии не реализован, поэтому backend честно откатывается на software.

Настройка применяется к новым окнам. `beyrix renderer` показывает выбор, `beyrix renderer list` перечисляет варианты, `beyrix renderer set NAME` сохраняет его в `config.toml`.

`beyrix gpu` выводит найденные DRM-устройства, реально созданный EGL/OpenGL-контекст с renderer-строкой, физические Vulkan-устройства из загрузчика, ICD-манифесты, выбранный backend и причину выбора. Наличие GPU только по PCI не считается доказательством ускорения: OpenGL проверяется созданием контекста, а программные реализации отличаются от аппаратных по renderer-строке.

OpenGL backend увеличивает потребление памяти на драйвер (на тестовой AMD Lucienne — примерно на 45–50 МиБ PSS) и немного замедляет запуск из-за инициализации EGL и компиляции шейдеров. Если важнее минимальная память, зафиксируйте `renderer = "software"`; на больших окнах и при интенсивной перерисовке GPU-путь снимает растеризацию с CPU, но общая скорость ввода-вывода может оставаться ограниченной парсером и прокруткой сетки.

OpenGL backend рисует фон, выделение, курсор и глифы на GPU. Глифы кэшируются в атласе и загружаются в текстуру только при первом использовании; прямоугольники и глифы батчатся в вершинные буферы. Изменённые строки перерисовываются частично через scissor; `EGL_KHR_swap_buffers_with_damage` сообщает композитору повреждённые области. При изменении размера, темы, масштаба или переключении редактора выполняется полная перерисовка. При ошибке драйвера или потере контекста backend один раз отключается и приложение продолжает работу через software без цикла повторной инициализации.

Дробное масштабирование поддерживается через `wp_fractional_scale_v1` + `wp_viewporter`, если композитор их предоставляет; иначе используется целочисленный `preferred_buffer_scale`. Software backend при дробном масштабе растягивается композитором (возможна небольшая потеря резкости), чтобы layout и координаты PTY оставались корректными.

## План Vulkan

Vulkan-рендеринг в этой версии намеренно не включён: обнаружение устройств работает, но backend не выдаётся за готовый. Следующий этап:

1. Использовать сцену `render::Scene` как общий контракт (она уже не зависит от OpenGL). Добавить `VkBackend`, который потребляет те же прямоугольники и глифы.
2. Через `ash`/`libvulkan` создать instance с `VK_KHR_wayland_surface`, выбрать физическое устройство (дискретное предпочтительнее, `PHYSICAL_DEVICE_TYPE_CPU` и lavapipe отклонять), создать device, queue и swapchain для `wl_surface`.
3. Переиспользовать атлас глифов как `R8_UNORM` текстуру и те же батчи; рисовать повреждённые строки через `VkRect2D` render area или очистку+scissor.
4. Добавить 2–3 кадра в полёте, semaphores/fences и синхронизацию с `wl_surface.frame`; корректно обрабатывать `VK_ERROR_OUT_OF_DATE_KHR`, `VK_SUBOPTIMAL_KHR`, resize и `VK_ERROR_DEVICE_LOST` с откатом на software.
5. Включить Vulkan в `auto` только после сравнительных замеров и проверки на RADV/ANV/NVIDIA/lavapipe; до этого `auto` выбирает OpenGL для аппаратного EGL-контекста.

Зависимость `ash` не добавлена, пока нет работающего backend, чтобы не увеличивать сборку и поверхность атаки без пользы.

## История и выделение

- `scrollback_limit` задаёт максимум сохранённых строк, от 0 до 100 000. Значение 0 отключает историю. Дополнительно полезная нагрузка строк истории ограничена 64 МиБ. При достижении любого лимита удаляются самые старые строки.
- `scroll_speed` задаёт число строк на один шаг колеса, от 1 до 100. Дробные смещения накапливаются. Shift+PageUp/PageDown листают историю, Shift+Home/End переходят к её началу или текущему выводу.
- История сохраняет исходную ширину строк. Узкое окно показывает видимую часть, а при расширении скрытые столбцы истории снова доступны. Активная сетка при сужении обрезается по ширине. Resize может сбросить выделение.
- Двойной клик выделяет слово, тройной — логическую строку с мягкими переносами. Удержание указателя у верхней или нижней границы текстовой области прокручивает историю при перетаскивании. Если история вытесняет выбранную строку, выделение сбрасывается.
- Ctrl+C копирует выделение. Без выделения Ctrl+C передаёт прерывание приложению. Ctrl+V вставляет из Wayland Clipboard с учётом bracketed paste.

## Редактирование команд

В интерактивном Bash графического Beyrix Ctrl+Left и Ctrl+Right перемещают курсор до ближайшей границы слева или справа. Ctrl+Backspace и Ctrl+Delete удаляют текст до той же границы. Слово состоит из любых символов, кроме пробела и табуляции. Соседние пробелы и табы образуют отдельный блок. Например, в конце `hello   world` три нажатия Ctrl+Backspace по очереди убирают `world`, три пробела и `hello`. В пути `/tmp/папка` слеши входят в слово.

Привязки действуют в режимах Emacs и Vi в Bash, запущенном графическим Beyrix. В UTF-8 локали границы вычисляются по символам. Обычные стрелки, Backspace, Delete и Ctrl+W используют встроенные действия readline.

Приложения получают Ctrl+Left и Ctrl+Right как `ESC [ 1 ; 5 D` и `ESC [ 1 ; 5 C`, Ctrl+Backspace как `ESC [ 127 ; 5 u`, а Ctrl+Delete как `ESC [ 3 ; 5 ~`. Поддержка модифицированных клавиш зависит от программы и её настроек. В частности, старые декодеры могут не распознать Ctrl+Backspace в формате CSI u. Автоповтор Wayland в Beyrix пока не реализован.

## Встроенный редактор

`beyrix edit FILE` открывает файл во встроенном редакторе. Если команда запущена в оболочке внутри Beyrix (переменная `BEYRIX_CONTROL_SOCKET` уже задана), запрос отправляется текущему окну; иначе открывается новое окно. Файл может ещё не существовать: он будет создан при первом сохранении. Поддерживается только UTF-8; BOM и переводы строк CRLF сохраняются.

- Ввод, `Enter`, `Tab`, `Backspace`, `Delete`; стрелки, `Home`/`End`, `Ctrl+←`/`Ctrl+→` по словам, `Ctrl+Home`/`Ctrl+End` по документу.
- `Shift` со стрелками и `Home`/`End` расширяет выделение; мышь выделяет текст перетаскиванием, двойной клик выделяет слово (с учётом Unicode и комбинирующих знаков).
- `Ctrl+C`, `Ctrl+X`, `Ctrl+V` работают через системный буфер Wayland.
- `Ctrl+S` сохраняет, `Ctrl+Z` отменяет, `Ctrl+Y` или `Ctrl+Shift+Z` повторяет, `Ctrl+A` выделяет всё.
- Колесо мыши листает файл; длинные строки прокручиваются по горизонтали.
- `Esc` возвращает в терминал. PTY, история и запущенные программы при этом не изменяются.
- Внизу показаны имя файла, признак изменений `[+]`, строка и столбец, кодировка и подсказки.

Сохранение атомарное: данные пишутся во временный файл в каталоге назначения, синхронизируются и заменяют исходный файл через `rename`. При ошибке записи исходный файл остаётся нетронутым. Права существующего файла сохраняются. Если файл изменился на диске или доступен только для чтения, первый `Ctrl+S` показывает предупреждение, а повторный `Ctrl+S` перезаписывает файл.

При `Esc` или закрытии окна с несохранёнными изменениями редактор показывает предупреждение: `Y` сохраняет и выходит, `N` выходит без сохранения, `C` или `Esc` отменяет выход. Если сохранение по `Y` не удалось, редактор остаётся открытым и показывает ошибку. Без изменений `Esc` сразу возвращает в терминал.

Ограничения версии 0.1: открыт один файл, нет вкладок, подсветки синтаксиса и LSP. Если окно уже занято файлом с несохранёнными изменениями, запрос `beyrix edit` отклоняется, но CLI не получает ответа по сокету и всё равно печатает, что запрос отправлен.
